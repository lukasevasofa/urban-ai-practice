# Обнинск — практическая работа № 2

Граница и 298 кварталов согласованы пользователем. Геометрия и ID сохранены без повторной нарезки.

- `obninsk_research.ipynb` — выполненный ноутбук: все расчёты, карты, таблицы и пояснения.
- `dashboard.html` — интерактивная карта, выбор 21 показателя, графики, таблица и экспорт CSV.
- `REPORT.md` — результаты, ограничения модели и качество данных.
- `validation_final.json` — результаты проверок и контрольные суммы файлов для практики №3.
- `practice3/` — готовый комплект исходных данных для сценариев 600 или 300+300 мест.

**Модель населения уточнена:** первоначальные 198 871 и исходные результаты сохранены в
`population_initial/`. Сады объясняли только 1 087 жителей. После проверки атрибутов выполнена условная
калибровка распределения к 133 000 на 01.01.2025 по жилой площади, без пропорции площадей территории.
Городской и муниципальный контуры OSM совпали; юридическая точность границ и разница дат остаются ограничениями.
Население кварталов и школьный дефицит — модельные, не официальные показатели. Подробности в `REPORT.md`.

## Повторный запуск из корня проекта

Расчёты и ноутбук на локальных данных, без новых запросов:

```sh
.venv/bin/python examples/data/obninsk/build_notebook.py
```

Только дашборд из сохранённых результатов:

```sh
.venv/bin/python examples/data/obninsk/generate_dashboard.py
```

Проверка результатов и комплекта для следующей работы:

```sh
.venv/bin/python examples/data/obninsk/verify_results.py
```

В VS Code выберите ядро существующего `.venv`. Исходник ячеек — `research_pipeline.py`;
`build_notebook.py` переносит его в ноутбук и выполняет. При редактировании расчётов меняйте этот исходник.
`prepare_review.py` относится к старому этапу согласования: не запускайте его для перезаписи итогового ноутбука.

## Сохранённые данные

- `blocks_review.geojson`, `approved_blocks.json` — согласованная основа и контрольная сумма.
- `blocks_results.geojson` / CSV — все показатели по `block_id` 0…297.
- `travel_time_minutes.csv` — матрица 298×298, минуты; строки и столбцы совпадают с `block_id`.
- `walk_graph.graphml` — полный пешеходный граф, скорость 4,5 км/ч, ребро `time_min` в минутах.
- `network_quality.json`, `residential_network_check.csv` — связность и качество привязки к сети.
- `buildings_raw.parquet`, `buildings_model.parquet` / GeoJSON — исходные и модельные атрибуты.
- `buildings_nested_excluded.parquet` — вложенные секции, исключённые из повторного учёта.
- `school_organizations.csv` — 24 организации; `school_catalog.csv` — 25 записей их размещения и корпусов.
- `schools.geojson` / CSV — источники мощности, исходные/модельные значения, доступность в основной модели.
- `school_parameters.json`, `baseline_provision.csv`, `school_allocation_links.csv` — параметры и исходная обеспеченность.
- `source_notes.json`, `sources/` — источники населения, школ, расхождения границ, результаты поиска готового графа.
- `dependency_versions.json` — фактические версии библиотек; зависимости окружения не переустанавливались.

OSM получен однократно стандартным API (четыре XML-фрагмента), поскольку три сервера Overpass оказались
недоступны. XML и объединённый JSON сохранены. `convert_osm.py` восстанавливает объединённый JSON из XML.
Повторное скачивание для запуска исследования не требуется. Готовый граф не найден в проверенных источниках;
построение OSMnx отмечено как отступление от задания.

Все обязательные показатели рассчитаны библиотечными функциями BlocksNet. Восстановление атрибутов и
приведение сохранённой OSM-выгрузки к графу выполняются простыми правилами, без ML.
Морфотипы без застройки и доля обеспеченности при нулевом спросе оставлены отсутствующими.

Дашборд открывается как обычный HTML; данные встроены. Подложка OSM, Leaflet и карты Folium требуют интернет.
Синтаксис и обработчики дашборда проверены в V8 с имитацией DOM/Leaflet; графический браузер не запускался.
В окружении есть предупреждение совместимости необязательного torch с NumPy, но используемые функции
нарезки, показателей, морфотипов, матрицы и обеспеченности выполнены успешно.

Источники: [OSM · ODbL](https://www.openstreetmap.org/relation/3396088),
[население администрации](https://obninsk.ru/obninsk/economic-development/stat/),
[школы](https://www.obninsk.ru/obninsk/social-sphere/education/Obninskschools/),
[задание](https://mvin8.github.io/ai-technologies-in-urbanism/content/practice/practice-02.html).
Изменения не публиковались на GitHub; исследования Кореновска и Кронштадта не изменялись.

## Материалы точечной корректировки населения

- `population_initial/` — полностью сохранённый первоначальный вариант.
- `population_scenarios.csv` — пять вариантов и их общая численность.
- `population_building_audit.csv` — атрибуты и население зданий до/после.
- `population_top10_blocks_audit.csv` — подробная проверка десяти самых населённых исходных кварталов.
- `population_block_comparison.csv` — население и школьная обеспеченность кварталов до/после.
- `population_scope_check.json` — основания и ограничения калибровки.
- `population_revision_locked_files.json` — зафиксированные контрольные суммы геометрий, графа и матриц.
- `population_revision.py` — короткие правила исправления атрибутов и распределения ориентира.

Обновление отчёта после расчёта: `.venv/bin/python examples/data/obninsk/update_report.py`.
