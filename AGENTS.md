# Инструкции для ИИ-агента

Учебный шаблон Python-пакета; поддерживается Python 3.10 и новее.

## Структура
- `my_package/` — код библиотеки; `my_module.py` содержит `MyClass` и функцию сложения `my_function`.
- `tests/` — тесты pytest.
- `examples/` — пример в Jupyter Notebook и данные в `examples/data/`.
- `docs/source/` — документация Sphinx в reStructuredText.
- `pyproject.toml` — зависимости, метаданные и настройки инструментов; `Makefile` — команды разработки.
- `.github/workflows/` — проверки, сборка документации и публикация пакета.

## Работа с проектом
- Вноси небольшие изменения по задаче, сохраняй существующие изменения пользователя. Не исправляй посторонние недочёты без запроса.
- Следуй текущему стилю: аннотации типов, docstring в стиле NumPy, строки до 120 символов; инструменты — Black, isort и pylint.
- Зависимости указывай в `pyproject.toml`, включая соответствующие группы `dev`, `tests` и `docs`.
- Установка для разработки и тестов: `python -m pip install -e '.[dev,tests]'` в виртуальном окружении. Установка пакета нужна и для получения версии через `importlib.metadata`.
- После изменения поведения добавляй подходящие тесты и запускай `python -m pytest tests` (или `make tests`); покрытие — `make tests-cov`, линтинг — `make lint`.
- `make format` изменяет файлы во всём `my_package/`; используй его только при подходящем объёме задачи.
- При изменении публичного API согласуй документацию и примеры. Сообщай, какие проверки выполнены и что не удалось проверить.

## Известные несоответствия шаблона
- В `Makefile` команда `install-test` использует extra `test`, но в `pyproject.toml` объявлен `tests`; устанавливай `.[tests]` напрямую.
- CI вызывает `make test`, хотя существующая цель называется `tests`.
- В метаданных указан `LICENCE`, тогда как файл лицензии называется `LICENSE`; это может мешать сборке и установке.
- README содержит пример импорта из `my_module_1`; фактический модуль — `my_package.my_module`.
