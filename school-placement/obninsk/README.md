# Обнинск: моделирование размещения школ

Практика №3 завершена: сохранены пользовательские А (№29), Б (№66 и №96) и В (№103).
Полный автоматический перебор 298 кварталов завершён без ошибок; найдено 69 равноценных оптимумов.
Итоговые выводы — в [REPORT.md](REPORT.md), сравнительная таблица —
в [results/final/scenario_comparison.csv](results/final/scenario_comparison.csv).
Все три сценария сокращают дефицит на 600 мест до 6 212; обеспеченность составляет 61,21%.
Инструкции ниже описывают работу приложения; сохранённый эксперимент повторять не требуется.

## Запуск

Из корня проекта, без установки дополнительных пакетов:

```sh
.venv/bin/python school-placement/obninsk/app.py
```

Откройте **http://127.0.0.1:8765**. Если сервер уже запущен агентом, повторно запускать команду не нужно.
Это приложение с Python-сервером: открытие `static/index.html` как обычного файла не запускает расчёты.
Для остановки сервера в своём терминале нажмите `Ctrl+C`. При занятом порте можно запустить с `--port 8767`.
Сервер всегда слушает только `127.0.0.1`.

Все данные локальные. Leaflet 1.9.4 уже сохранён в `static/vendor/`; сеть нужна только для подложки OpenStreetMap.
Без подложки границы, выбор кварталов, таблицы и расчёты продолжают работать.
Рабочее окружение `.venv` не переустанавливалось; Flask, базы данных, платные сервисы и языковые модели не используются.

## Порядок проведения эксперимента: сначала ручные варианты

1. Изучите карту в режиме **«Исходное состояние»**, карточки кварталов и таблицу. Квартал выбирается нажатием на карту
   или через список ID. Изначально ни один квартал не выбран.
2. Для **А** добавьте одну школу на **600 мест** в выбранном вами квартале. Нажмите «Рассчитать сценарий».
   Выберите тип «А», запишите название и **собственное обоснование**, затем сохраните вариант.
3. Нажмите **«Сбросить план»** — сохранённый А останется в сравнении. Для **Б** добавьте две школы по **300 мест**
   в разных кварталах. Рассчитайте, выберите тип «Б», обоснуйте и сохраните.
4. Школы в текущем плане можно редактировать и удалять. После изменения план нужно пересчитать;
   до этого карта и таблица возвращаются к исходной модели и явно сообщают, что изменения ещё не рассчитаны.
5. Когда ручной выбор согласован, нажмите **«Подтвердить А и Б и открыть автопоиск»**.
   Это отдельное осознанное действие пользователя: само по себе оно **не запускает** поиск.
   После подтверждения исходные ручные А/Б больше не переписываются задним числом.

Агент не выбирал за вас ручные кварталы. Технические тесты выполнялись на отдельных малых приростах мощности;
их сохранения изолированы в `runtime/` и не входят в рабочие сценарии пользователя.

## Автоматический поиск — только после ручных вариантов

После подтверждения А/Б задайте вместимость и нажмите «Разместить автоматически».
Все **298 кварталов** проверяются по одному и независимо от текущего плана. На каждой итерации используется
исходная мощность сети плюс одна новая школа, без накопления мест. Прогресс, ошибки и все строки результатов
отображаются в приложении. Критерий — сокращение общего неудовлетворённого спроса.

Все равноценные лучшие кварталы выводятся только при успешном завершении всех 298 расчётов.
При ошибках, остановке или прерывании сервера поиск явно считается неполным, без заявления об оптимуме.
Можно выбрать строку таблицы или кнопку лучшего квартала: приложение пересчитает этот вариант и покажет его на карте.
Для итогового **В** выберите один из лучших кварталов полного поиска **600 мест** и сохраните тип «В».
Автоматического подбора двух школ нет.

## Карта, сравнение и экспорт

- Три режима: исходная обеспеченность, рассчитанный сценарий, изменение в процентных пунктах.
- Для исходного состояния и сценария одна шкала **0–100%**; для изменений — отдельная двусторонняя шкала.
- Серый означает отсутствие спроса, а не нулевую обеспеченность. Для выбранного квартала видны значения до и после.
- Существующие муниципальные школы — зелёные точки, частные/специальные — серые, новые — пурпурные маркеры кварталов.
- Таблицы сортируются нажатием на заголовки; строка квартала или сценария связывается с картой.
- Сохранённые варианты сравниваются в таблице и двух диаграммах. Экспорт CSV доступен для кварталов, сценариев и перебора.
- CSV использует UTF-8 с BOM и разделитель `;`, пустое поле обозначает отсутствующее значение.
- Сброс очищает текущий план и восстанавливает исходный расчёт; сохранённые сценарии не удаляются.

## Исходная модель и методика

Используются **только окончательные входные файлы** из `examples/data/obninsk/practice3/`, только для чтения.
Архив первоначальной модели не читается; практика №2 не исправляется.

Исходный расчёт реально воспроизведён и совпал со всеми сохранёнными колонками и кварталами:

| Показатель | Значение |
|---|---:|
| Кварталов | 298 |
| Модельное население | 133 000 |
| Расчётная потребность | 16 015 мест |
| Мощность сети | 9 664 места |
| Обслуженный спрос | 9 203 места |
| Обеспеченность | 57,46% |
| Остаточный дефицит | 6 812 мест |

Во всех сценариях используется `BlocksNet 1.0.0a9 competitive_provision`, 120 мест/1000 жителей,
15 минут, `self_supply=True`, `max_depth=1`, та же матрица минут. Спрос округляется вверх по кварталам.
Меняется только мощность выбранных кварталов. Суммировать население и вычитать общее количество мест недостаточно:
проводится конкурентное пространственное распределение спроса по всей территории.

**Ограничения.** Население — условное распределение ориентира на 01.01.2025 по жилой площади OSM 2026,
а не официальное население кварталов. Мощность большинства школ оценена по площади / 18 м² на место;
частные и специальные учреждения не включены в неограниченную общедоступную мощность.
Граф самостоятельно построен по пешеходной сети OSM, скорость 4,5 км/ч; подходы к узлам и внутриквартальные пути
в матрицу не добавлены. Своему кварталу мощность распределяется первой. Функция BlocksNet оптимизирует взвешенные
потоки, поэтому возможны перераспределение и ухудшение отдельных кварталов при улучшении общего показателя.
Эффективный квартал не подтверждает наличие подходящего участка или возможность строительства.

Источники: [задание преподавателя](https://mvin8.github.io/ai-technologies-in-urbanism/content/practice/practice-03.html),
[OSM · ODbL](https://www.openstreetmap.org/relation/3396088),
[статистика администрации](https://obninsk.ru/obninsk/economic-development/stat/),
[каталог школ](https://www.obninsk.ru/obninsk/social-sphere/education/Obninskschools/).
Картографическая библиотека — [Leaflet](https://leafletjs.com/), лицензия BSD-2-Clause.

## Файлы

- `app.py` — локальный сервер, сохранение и последовательность эксперимента.
- `model.py` — загрузка входных данных, воспроизведение исходного расчёта, независимый сценарий и цикл перебора.
- `static/index.html`, `app.js`, `style.css` — интерфейс; `static/vendor/` — локальная библиотека карты.
- `results/baseline.json`, CSV, `baseline_check.json` — воспроизведённый исходный расчёт.
- `results/input_manifest.json` — контрольные суммы всех входных файлов.
- `results/latest.json`, CSV — последний расчёт в рабочем приложении.
- `results/scenarios.json`, `scenario_*.json`, CSV — сохранённые сценарии, обоснования и результаты.
- `results/auto_*.json` — сохранённые прогресс и итоги настоящего перебора.
- `tests/` — проверки; `runtime/` — временные файлы и изолированные тестовые результаты.
- `REPORT.md` — текущая стадия практики и выполненные проверки.

Повторная проверка без реального автопоиска:

```sh
.venv/bin/python -m pytest school-placement/obninsk/tests -q \
  -o cache_dir=school-placement/obninsk/runtime/pytest \
  --basetemp=school-placement/obninsk/runtime/test-run
```

Полный перебор реального Обнинска намеренно не выполняется тестами до вашего выбора А/Б.
Его механизм, независимость 298 итераций, равенства и ошибки проверяются на синтетических данных.

Проверены 19 тестов Python и 25 действий в настоящем WebKit macOS; отчёты — `results/python_tests.xml`,
`results/browser_check.json` и `results/verification.json`. Проверка WebKit использовала отдельный тестовый сервер,
не выбирала рабочие А/Б и не запускала реальный поиск. Снимки итогового интерфейса — в `docs/img/obninsk/` от корня проекта.
Для работы приложения компиляция браузерного теста не требуется.

## Итоговая проверка сохранённого эксперимента

```sh
.venv/bin/python school-placement/obninsk/finalize_experiment.py
```

Команда сверяет сохранённые А/Б/В и все 298 результатов перебора, повторяет ручной расчёт №103
и отдельный диагностический вариант №32. Новый полный поиск не запускается, исходные данные и пользовательские
сценарии не перезаписываются. Обновляются только итоговый отчёт и файлы `results/final/`.
Протокол — `results/final/verification.json`; итоговые CSV имеют UTF-8 с BOM и разделитель запятую
(экспорт из интерфейса по-прежнему использует точку с запятой).
`verify_release.py` относится к стадии до пользовательского эксперимента; его условие отсутствия
автопоиска после завершения эксперимента неприменимо.
